# 体积云（近地）

相机降到约 300 km 以下时，`viewer.clouds` 从覆盖全球的云壳过渡到立体的积云层：可以从地面仰望、飞进云里、从云上俯瞰，开"太阳光照"时云在地面、建筑和 3D Tiles 上投下随风移动的影子。API 见 [docs/api.md](../api.md) §1.13；远看的云壳见 [intro-and-navigation.md](intro-and-navigation.md) §3。

| 模块 | 职责 |
| --- | --- |
| `clouds/VolumetricClouds.ts` | 后期效果（linear 阶段，`order = -50`）：渲染目标、帧状态（风、天气图锚点、重投影的上一帧位姿）、噪声体、何时重画天气图和云影图 |
| `clouds/cloudNodes.ts` | 五个 pass 的 TSL 节点图（天气图、云影图、追踪、时域重投影、合成）和它们共用的部分（云层求交、天气查找、密度、光线步进、相函数），只构建节点、不持有状态 |
| `clouds/volumetricCloudMath.ts` | 选项与夹紧、高度淡出、云层球壳求交（与着色器同一套公式）、步长增长、历史尺寸、交错顺序、天气图范围、噪声坐标取模（纯函数，有单测） |
| `clouds/cloudNoise.ts` / `cloudNoise.worker.ts` | 可平铺的 3D 噪声（Perlin-Worley + 三个单八度 Worley，64³ RGBA8，1 MB），在 Worker 里生成（约 0.5 s），整页共享 |
| `lighting/cloudShadows.ts` | 云影的共享接收节点，乘进 `sunShadowFactor()`，只削弱直射阳光 |
| `clouds/CloudLayer.ts` | 选项（`volumetric`），云壳密度节点 `densityNode`（天气跟随云壳） |

## 1. 参考与来源

做法参考 [yisky/hillaire-sky-webgpu](https://github.com/yisky/hillaire-sky-webgpu) 的积云部分（SkyPro "Partly cloudy" 风格：天气图 + 形状 / 侵蚀噪声、低分辨率交错追踪、按云距离的时域重投影）和两篇公开资料：Schneider，"The Real-time Volumetric Cloudscapes of Horizon Zero Dawn"（SIGGRAPH 2015，噪声布局、密度重映射、粉末效应）；Hillaire，"Physically Based Sky, Atmosphere and Cloud Rendering in Frostbite"（SIGGRAPH 2016，能量守恒积分、多次散射的倍频近似）。

**该参考仓库没有许可证文件（默认保留所有权利），本仓库没有复制其代码和噪声二进制文件**，只借鉴思路，代码全部重写。不同之处：

| 项 | 参考仓库 | 本仓库 |
| --- | --- | --- |
| 着色器 | 手写 WGSL compute（只能 WebGPU） | TSL 片元 pass（WebGPU 和 WebGL 2 都能跑） |
| 场景 | 平面地面、相机在地面附近，云只画进天空背景 | 球面、相机从地面到太空；云在后期里按场景深度合成，山体可以插进云里、相机可以在云上 |
| 天气 | 一张固定的 1024² 天气图 | 天气跟随全球云壳的密度（从太空看到的云就在底下），世界空间的 3D 噪声，按相机锚定、随风滑动的 1024² 天气图（`low` 档 512²） |
| 噪声 | 预生成的 64³ 文件 | Worker 里程序生成，单八度通道，着色器按像素足迹逐八度淡出（体纹理没有 mip） |
| 地面云影 | 没有 | 沿太阳光线的正交透射率图，所有受光材质经 `sunShadowFactor` 接收 |
| 大气 | 自己的三张查找表 | 复用本仓库的大气积分做云的空气透视，光照用 CPU 版大气（`AtmosphereLighting`）的太阳颜色和天光 SH |

## 2. 渲染流程

每个画出的帧（静止 / 降帧时不画就不算）：

| 步骤 | 时机 | 做什么 | 分辨率 |
| --- | --- | --- | --- |
| 1. 天气图 | 场景 pass 之前，只在锚点、风、设置变了时 | `presence`（这里有没有云）、`tops`（云顶相对高度）；见 §3 | 1024² RGBA8（`low` 512²） |
| 2. 云影图 | 场景 pass 之前，开光照且太阳在地平线上时每帧 | 沿太阳光线穿过云层 12 步，存透射率 | 按档位 256–1024² RGBA8 |
| 3. 绑定 | 同上，帧外渲染（截图、层级截帧）也做 | 把本 viewer 的云影图和矩阵写进共享接收节点的 uniform | — |
| 4. 追踪 | 场景 pass 之后（`prepare`） | 历史分辨率的 1/4 像素：每个 2×2 块本帧只追一个（`INTERLEAVE_SLOTS`，4 帧一轮）；MRT 输出（散射光, 不透明度）和（云距离 km, 场景视深 km） | 历史的一半 |
| 5. 时域合成 | 同上 | 写进另一张历史（乒乓）：本帧追到的像素与重投影的旧值混合（新样本占 30%），其余像素只用重投影的旧值；旧值夹在新样本 3×3 邻域的范围内；场景深度对不上（换成了别的表面）时丢弃旧值 | 至多画布一半、按档位 0.16–1 百万像素 |
| 6. 合成 | 最终后期图（`build`） | 2×2 双线性取历史，按场景视深加权（建筑边缘不粘云）；`color × (1 − α) + 云` | 画布 |

重投影：历史像素的视线乘上云距离得到云的位置，减去相机的位移和这一帧的风位移，用上一帧相机的旋转和投影矩阵投回去。相机位移、风位移都是 CPU 上 float64 相减后的小量。没有云的像素存"云层在这条视线上的中点"作为距离：存固定的 40 km 时，从 120 km 高空看（云在 150 km 外），重投影的距离错了好几倍，随风移动的云拖出长条（§7）。

## 3. 天气与密度

**天气图**按相机正下方的锚点（椭球面上，ENU 坐标）展开，宽度 = 2 ×（`maxDistance` + 2 × 15 km），高空时加到 4 × 相机高度，最多 440 km：相机在约 35 km 以上时就是这个宽度。边长按档位（`GpuProfile.clouds.weatherSize`）：1024²（纹素 ≤ 430 m，天气格的八分之一），`low` 档 512²（≤ 860 m，四分之一；更粗时云格被抹平、整片变成均匀的薄雾）。512² 时每个云格只有约 4 个纹素，双线性插值把它画成和纹理坐标轴对齐的圆角方块，相邻的云连成一片，40–200 km 高看得出方块感（B12）；1024² 与 2048² 的画面只差 0.1–1 % 的像素，2048² 没有必要。每个纹素：

- `macro`：全球云壳在这个方向的密度（`CloudLayer.densityNode`，与云壳着色器同一个节点函数、同一组 uniform）。从太空看到的云团所在处，底下是成片的积云；云壳晴空处，底下是零散的淡积云。
- 云格：噪声的 G、B 通道（Worley 4、8 格 / 14 km）；云团：R 通道（Perlin-Worley / 60 km）；云顶：R 通道（/ 23 km）。都在 ECEF 里取样（`(锚点 − 风位移) / 周期` 在 CPU 上 float64 取模），换锚点时内容不跳。
- `presence = smoothstep(阈值 ± 宽度, 0.75·云格 + 0.35·云团 − 0.1)`，阈值由 `coverage` 和 `macro` 决定（覆盖率 0.5、云壳晴空时约 10%，云壳浓云处约 90%）。宽度至少 ±0.13，纹素超过 600 m 时按纹素放宽（窄边缘在粗网格上会显出台阶）。试过把"到阈值的距离"存进图里、查图之后再做 smoothstep（距离场的做法），画面只变了 0.6 % 的像素：方块感来自分辨率，不是插值次序，所以没有采用。

查天气时按 `ENU(点 − 锚点) − ENU(风位移 − 烘焙时的风位移)` 取，所以图本身随风滑动；滑出 15 km、相机离开锚点 15 km、范围变了 20% 以上或设置变了才重画。

**密度**（Schneider 的重映射）：

```
云顶 = mix(0.4, 1, tops) × mix(0.25, 1, √presence)       // 云的边缘低、中心高：圆顶
剖面 = smoothstep(0, 0.06, hf) × (1 − smoothstep(0.7·云顶, 云顶, hf))   // 平底，只在顶部收尖
形状 = remap(R, lowFbm − 1, 1, 0, 1)                        // lowFbm = G·0.625 + B·0.25 + A·0.125
密度 = saturate(形状 × 剖面 + presence − 1)
细节 = 侵蚀(密度, 细节噪声)                                // 底部丝缕、上部翻卷，只在 75 m 足迹以内
```

形状噪声周期 4.5 km（风切变：越高处越往上风方向取样，云顶顺风倾斜），细节噪声 600 m。体纹理没有 mip：每个 Worley 八度在其格子小于约两个像素足迹时淡出到均值（`worleyFbm`），细节在足迹超过 75 m 时整个不取样。没有这一步，远处的云边是一圈闪烁的"毛刺"。

## 4. 光照

- 太阳：开光照时为真实太阳方向，颜色用 `AtmosphereLighting` 在视点下方地面算出的太阳透射率（与建筑、3D Tiles 的平行光同一个值）；关光照时为相机正上方的白光（"影棚"）。
- 朝太阳方向 4–6 步（几何增长，最远约一个云层厚度）累加光学深度，不取细节。
- 多次散射：三个倍频 `Σ aⁱ · P(cosθ, gⁱ) · exp(−τ·bⁱ)`（a = 0.6、b = 0.35 / 0.12、相位各向异性每次减半），相位是双瓣 Henyey-Greenstein（前向 0.8 的银边 + 后向 −0.25），按 4π 归一（各向同性 = 1）。
- 粉末效应：薄处背光面略暗。
- 天光：由天光 SH 算出向上、向下的辐照度 / π，按云内高度在两者之间插值（云底偏暗、云顶偏亮）；夜里留一点底光。
- 能量守恒积分（Hillaire 2016）：每步 `L += T·(1 − e^{−σΔs})·S`、`T *= e^{−σΔs}`，消光 0.05 / m × `density`，反照率 0.97。
- 空气透视：在云的不透明度加权平均距离处做与建筑相同的大气积分（`aerialScatteringAlong`，6 步）：`L' = L·T_atm + 内散射·groundHaze·α`。
- 远处变薄：进入云层后超过 `maxDistance` 的 65% 起逐渐透明，不出现截断线。

## 5. 步进

视线与两个同心球壳（云底、云顶，半径 = 相机处的高斯曲率半径 √(M·N) + 高度）求交，公式写成 `(h0 − hs)(2R + h0 + hs)` 和稳定根形式，float32 下 100 km 内误差在米级以下（`shellRoots`、`cloudInterval` 有 CPU 版和单测）。高度沿视线用 `h0 + q / (√(r0² + q) + r0)` 求，不出现 ECEF 大数相减。

- 云外大步（随走过的距离增长，`stepGrowth` 让预算步数正好走到 `maxDistance`；不取细节，只做命中测试）；命中后退回上一步、改用小步（像素足迹的 1.5 倍，至少 `厚度 / 90`）；连续 3 个空样本后再改回大步。
- 起点按交错梯度噪声 + 帧号偏移抖动，历史把抖动平均掉。
- 透射率低于 1% 提前结束；场景深度（地形、建筑、3D Tiles）截断视线，所以山体和楼插进云里、云在山后被挡住。

## 6. 与其他功能的关系

| 功能 | 关系 |
| --- | --- |
| 云壳（`CloudLayer`） | 共用 `visible`、`coverage`；云壳在 60–500 km 之间淡入，体积云在 100–300 km 之间淡出，中间两者叠加。云壳的漂移只在云壳可见时推进（近地时天气不动），并且被当作风：漂移把云壳的云绕地轴转过的位移累加到风位移里，云格、形状、天气图、重投影一起移动 |
| 帧率（[api.md](../api.md) §1.8） | 有风时云一直在动，画面不算静止：按最近的云在屏幕上的移动速度要最低帧率（每帧 ≤ 1.5 px，`volumetricCloudFrameRate`；6 m/s 时云底下 1 km 约 4 帧/秒，云层里约 14 帧/秒）。风速为 0 时云不动，画面可以静止并做超采样，超采样的抖动样本也继续给云的历史加样本 |
| 日照阴影 | 云影乘进同一个 `sunShadowFactor()`；有云影时太阳光的 `castShadow` 也打开（即使建筑阴影关着），切换时带光照的材质重编一次 |
| 局部场景、展台背景 | 进入局部场景或建筑周围什么都不画（展台背景）时不画体积云 |
| 拾取、顶牌遮挡 | 不参与：云是后期效果，不写深度 |
| 多个 viewer | 噪声数据整页共享（只读）；云影的接收 uniform 是模块级的，每个 viewer 渲染前绑定自己的（docs/api.md §4） |

## 7. 踩过的坑

- **云边一圈毛刺**：体纹理没有 mip，远处的高频八度欠采样；而原来的通道本身混着多个八度，没法只去掉太细的那部分。改成单八度通道 + 着色器里逐八度按足迹淡出，细节超过足迹上限不取样。
- **远处的云糊成块、拖成长条**：原来的步长随距离几何增长，20 km 外每步约 500 m，比云还大。改成云外大步、云内按像素足迹的小步，进云时退回一步。
- **云像箱子 / 圆锥**：天气的边缘太窄，形状噪声来不及把它雕成团块，得到竖直的墙；云顶高度随边缘线性降低又成了圆锥。边缘加宽、云顶按 √presence 下降、剖面只在顶部 30% 收尖。
- **高空随漂移拖出条纹**：没有云的像素原来存固定的 40 km 作为重投影距离，从 120 km 高空看（云在 150 km 外）时与有云像素混合后距离错了好几倍。改为存视线在云层里的中点，邻域估计按不透明度加权。
- **高空整片变成薄雾**：天气图随高度放大到 1200 km 时纹素 2.3 km，云格被抹成均值，阈值附近一片半透明。天气图最多 440 km，再远的云在图边淡出（那里云壳已经接手）。
- **TSL `If(c, () => x.assign(...))`**：箭头函数把赋值节点当返回值，three 生成一条被注释掉的 `return` 并警告（"Return statement used in an inline Fn()"）。`If` 的回调写成块 `{ x.assign(...); }`。
- **临时向量被改写**：把模块级的临时 `Vector3` 传给内部也用它做临时变量的函数，云影图的中心和法线被改坏，影子整个落在图外（看起来像没有云影）。传给别的函数的向量用专门的字段。

## 8. 档位与开销

| 档位 | 默认 | 历史像素上限 | 步数 | 朝太阳步数 | 云影图 | 天气图 |
| --- | --- | --- | --- | --- | --- | --- |
| `low` | 关 | 16 万 | 48 | 4 | 256² | 512² |
| `medium` | 开 | 30 万 | 64 | 5 | 512² | 1024² |
| `high` | 开 | 52 万 | 96 | 6 | 512² | 1024² |
| `ultra` | 开 | 100 万 | 128 | 6 | 1024² | 1024² |

`low` 默认关（2026-11-24 在集成显卡上实测后维持，§10）：`low` 档面向比当前集成显卡更弱的设备，在 Intel Arc 集显上 `low` 档的云每帧多 1.4–2.3 ms，换到慢 3–5 倍的设备上就是 4–10 ms，作为默认太贵；宿主可以用 `clouds.set({ volumetric: true })` 打开。

显存（第一次显示时分配，计入 `viewer.memory.framebuffers`，经 `postProcessing.gpuBytes`）：噪声 1 MB、天气图 4 MB（`low` 1 MB）、云影图 0.25–4 MB、追踪目标（历史的 1/4，2 × RGBA16F）、两张历史（各 2 × RGBA16F）。1280×720、`high`：约 14 MB；1920×1080：约 24 MB（天气图 512² 时各少 3 MB）。

开销以追踪为主，见 §10。

浏览器手测清单：

- 地面仰视（`#116.39,39.9,600,90,8`）：云底平、云顶圆，向阳面亮、背光面暗，远处的云融进大气，没有截断线；右键拖动转视角时云不拖影。

- `?webgl`：画面一致。`?gpu=low`：默认没有体积云。

## 10. 实测（2026-11-24）

WebGPU、RTX 40 系，无头 Chrome，离线调试影像，每帧都画（`?idleFps=0&ss=0`），开光照。每个 pass 每帧额外重画 20 次，取整帧 GPU 时间的增量 / 20（整帧只有 1–4 ms 时 GPU 降频，直接比较开关云的整帧时间不可靠，开云反而更快）。

| --- | --- | --- | --- | --- | --- | --- | --- |
| `high` | 1280×720 | 地面仰视 | 640×360 | 0.25 ms | 0.03 ms | 0.04 ms | 0.09 ms |
| `high` | 1920×1080 | 地面仰视 | 960×540 | 0.60 ms | < 0.01 ms | < 0.01 ms | 0.02 ms |
| `high` | 1920×1080 | 9 km 俯视 | 960×540 | 0.38 ms | < 0.01 ms | < 0.01 ms | 0.02 ms |

**集成显卡（2026-11-24，B12 / B13）**：Intel Arc（Meteor Lake，`intel xe-lpg`，按 `classifyGpu` 是 `medium` 档），同一台笔记本，无头 Chrome。Chrome 的 GPU 进程跑在独立显卡上，WebGPU 只拿得到它；用 `--use-adapter-luid=<chrome://gpu 里集显的 LUID>` 让 GPU 进程改用集显。1920×1080、DPR 1、离线调试影像、开光照，天气图按档位（`low` 512²，`medium` 1024²）。

测法：停掉帧循环，连续提交 24 帧（云的图 + 后期管线整帧）后等 GPU 队列排空，取每帧耗时；三种状态（开云、开云但不画云影、关云）每轮换一次顺序，共 5 轮取中位数。集显上不要用 `stats.gpuMs` 比较开关：同一状态的读数在几秒内能差 3–8 ms（功耗状态切换），B12 第一次测出的"云影多 4 ms""俯视降到 47 FPS"都是这种波动。持续满载几分钟后集显会降频，整帧时间成倍上升，那几轮只能看同一轮内的差值。
