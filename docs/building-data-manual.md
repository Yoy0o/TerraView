# 建筑数据制作手册（three-geo-building v1.0）

本手册说明如何为 TerraView 制作建筑数据：一个 `*.building.json` 文件描述一栋建筑的地理位置、楼层、房间、设备和构件，可选地引用 glTF 模型。加载后可以从地球无缝进入建筑、楼层、房间，查询实体、查看属性、挂顶牌。

- **读者**：负责整理 BIM / CAD / 资产数据的同事，以及把数据接入页面的前端开发者。
- **完整样例**：[examples/sample-office.building.json](examples/sample-office.building.json)（地下 1 层、地上 2 层，用到了本手册的全部字段；单元测试会校验它，保证与代码一致）。
- **格式定义的代码**：`src/indoor/schema.ts`（类型与校验）、`src/indoor/Building.ts`（几何生成）。运行时行为见 [agents/indoor-bim.md](agents/indoor-bim.md)。

## 1. 快速开始

最小的可用文件只要格式标识、锚点和一个楼层：

```json
{
  "format": "three-geo-building",
  "version": "1.0",
  "id": "my-building",
  "name": "我的建筑",
  "anchor": { "longitude": 116.3975, "latitude": 39.999, "heading": 0 },
  "floors": [
    {
      "id": "MB-F1", "name": "1F", "index": 0, "elevation": 0, "height": 4,
      "rooms": [{ "id": "MB-F1-R01", "name": "101", "category": "office", "footprint": [[0, 0], [8, 0], [8, 6], [0, 6]] }]
    }
  ]
}
```

加载方式（任选其一）：

| 方式 | 说明 |
| --- | --- |
| 拖入页面 | 文件名以 `.building.json` 结尾，直接拖到浏览器窗口 |
| 面板 | "室内 / BIM" → "打开 building.json…" 或填写 URL 后点"加载" |
| URL 参数 | `?building=<文件地址>`，可重复；开发服务器下样例可用 `?building=/docs/examples/sample-office.building.json` |
| 代码 | `viewer.indoor.add(doc, baseUrl)`，`baseUrl` 用来解析模型的相对路径 |

加载成功后相机会飞到建筑。双击建筑进入，双击楼层、房间逐级进入，右键单击或 Esc 返回。文件有错误时，页面提示里会给出带 JSON 路径的错误信息（见 §9.1）。

## 2. 数据模型

### 2.1 层级

```
建筑 building（IfcBuilding）
├─ 外壳 exterior（从地球上看到的外立面和屋顶；进入建筑后隐藏）
└─ 楼层 floor（IfcBuildingStorey）× n
   ├─ 房间 room（IfcSpace）：多边形轮廓，自动计算面积，自动生成墙和门洞
   ├─ 设备 thing（IfcElement：设备、传感器、资产、家具）
   └─ 构件 element（墙、门、窗、柱、楼板、楼梯）
```

- 设备和构件挂在**楼层**下，而不是房间下。设备属于哪个房间由位置决定：设备的位置落在房间轮廓内，就算在这个房间里。进入房间时，房间里的设备保持清晰，其他实体变淡。
- 文档里列出的每一项都是**托管实体**：可以拾取、高亮、查询、改样式、挂顶牌。glTF 模型里没有对应实体的节点只是**静态几何**，照常显示，点到时解析为它所在的楼层或设备。

### 2.2 三种做法

| 做法 | 适用 | 要点 |
| --- | --- | --- |
| 纯参数化 | 没有 BIM 模型，只有平面图或资产台账 | 房间写轮廓和门洞，设备写位置和尺寸，墙、楼板自动生成 |
| 整层 glTF | 已有 BIM 导出的楼层模型 | `floor.model` 引用模型；模型节点名等于房间、设备、构件的 `id` 时，就挂到对应实体上 |
| 混合 | 常见做法 | 楼层用 glTF 显示真实外观，房间写轮廓（`walls: false`）用于交互、面积和顶牌，关键设备单独列出 |

### 2.3 制作流程

1. 确定锚点：建筑本地原点的经纬度、本地 +Y 轴的朝向、是否写高度（§3）。
2. 列楼层表：编号、名称、标高、层高（§4.3）。
3. 逐层画房间轮廓、标门洞（§4.4）。
4. 列设备：位置、尺寸、类别、属性、顶牌（§4.5、§5.3）。
5. 补构件：柱、门、窗、楼梯等需要单独交互的结构（§4.6）。
6. （可选）挂 glTF 模型并核对节点命名（§7）。
7. 给需要分组的实体打标签，给重要层级配视点（§4.8、§4.9）。
8. 加载自检（§9）。

## 3. 坐标、朝向与高度

### 3.1 建筑本地坐标

- 单位：米。
- 原点：`anchor` 指定的经纬度点。可以选建筑中心、某个角点或轴网交点，选定后全文件统一。
- 轴向：+X 指向"本地东"，+Y 指向"本地北"，+Z 向上。
- `anchor.heading`：本地 +Y 轴相对**正北顺时针**转过的角度（度）。建筑轴网与正南北对齐时写 0；轴网"北"偏东 15° 时写 15。CAD 图纸可以直接按轴网画，旋转交给 `heading`。

```
        正北
         ↑   ↗ 本地 +Y（heading = 15°）
         │  /
         │ /
         │/
  原点 ●────────→ 本地 +X
```

### 3.2 楼层内坐标

楼层内的房间、设备、构件都用**楼层本地坐标**：XY 与建筑本地坐标相同，Z = 0 是本层楼面（楼板上表面），不是建筑原点。每层的 Z 偏移由楼层的 `elevation` 统一给出，所以各层可以复用同一套平面坐标。

### 3.3 高度（`anchor.height`）

- `anchor.height` 是 **WGS84 椭球高**（米），不是海拔。椭球高 = 海拔 + 当地高程异常，两者在国内可能相差几米到几十米。
- **省略** `anchor.height`：建筑自动贴到地球地形上。地形细化到足够精度（网格间距 150 m 以内）后才贴，之后随地形细化微调。大多数情况推荐省略。
- **必须写明高度的情况**：
  - 场景使用 **Google 真实感 3D Tiles 等倾斜摄影**，而建筑锚点正好落在倾斜摄影里的屋顶、树冠、高架上：地球隐藏时贴地以 3D Tiles 最上层表面为准，会贴到这些物体上面。锚点在空地上时可以省略（[ISSUE-1](agents/roadmap.md) 已修复）。
  - 建筑建在高架、屋顶或地形数据不准的位置。
- **取得椭球高**：在页面上飞到建筑位置，让地面（地形或 3D Tiles）位于屏幕中心，在浏览器控制台执行：

  ```js
  viewer.pickCartographic(innerWidth / 2, innerHeight / 2).height  // 屏幕中心地面的椭球高（米）
  ```

  如果本地原点不在室外地坪（例如原点取在 1F 楼面、而 1F 比室外高 0.45 m），把差值加上。

### 3.4 多边形规则

房间轮廓、楼层轮廓、建筑轮廓、楼板路径都是 `[[x, y], ...]` 点列：

- 至少 3 个点；首尾**不要**重复。
- 推荐逆时针（从上往下看）。顺时针也可以，程序会自动翻转，门洞的边号仍按你写的顺序计算。
- 不能自相交；暂不支持带洞多边形（中庭、天井请拆成多个房间或用楼层轮廓表达）。
- 相邻房间共用边时写成完全相同的坐标：自动生成的墙会各自向内缩半个墙厚，背靠背不会重叠闪烁。

## 4. 字段说明

### 4.1 通用字段（所有元素都可以写）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | 字符串 | 是 | 全文件唯一（楼层、房间、设备、构件之间也不能重复），推荐用 IFC GlobalId 或编码规则（§8） |
| `name` | 字符串 | 否 | 显示名称，默认取 `id`（楼层默认 `index + 1` 加 "F"） |
| `category` | 字符串 | 否 | 分类，决定默认配色，也用于查询，见 §5。不写时为实体类型本身（`building` / `floor` / `room` / `thing`），构件为 `kind` |
| `ifcType` | 字符串 | 否 | 来源 IFC 类名，如 `IfcSpace`，仅保留不参与计算 |
| `properties` | 对象 | 否 | 属性表，弹窗里逐项显示，可用于查询，见 §6 |
| `tags` | 字符串数组 | 否 | 标签，用于分组查询和层级规则，见 §5.6 |
| `viewpoint` | 对象 | 否 | 进入该层级时的相机视点，见 §4.9 |
| `label` | 对象 | 否 | 顶牌（头顶标签），见 §4.8 |

### 4.2 建筑（根对象）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `format` | 字符串 | 是 | 固定为 `"three-geo-building"` |
| `version` | 字符串 | 是 | `"1.0"`。主版本号必须是 1 |
| `anchor.longitude` / `anchor.latitude` | 数字 | 是 | 本地原点的经度、纬度（度，WGS84） |
| `anchor.height` | 数字 | 否 | 本地原点的椭球高（米），省略则贴地，见 §3.3 |
| `anchor.heading` | 数字 | 否 | 本地 +Y 轴相对正北顺时针的角度（度），默认 0 |
| `footprint` | 点列 | 否 | 建筑外轮廓（本地米），用于生成外壳和默认楼板。省略时取所有楼层轮廓和房间的外包矩形 |
| `exterior` | 对象 | 否 | 外壳：`{ "model": {...} }` 用模型，或 `{ "color": "#86a9d4", "opacity": 0.5 }` 用程序生成的玻璃幕墙（默认 `#8fb3d9`、0.5），外加每层的楼板腰线和屋顶 |
| `floors` | 数组 | 是 | 至少一层，见 §4.3 |

程序会在建筑的属性里自动加上 `楼层数`、`建筑高度`；文档里写了同名属性时以文档为准。

### 4.3 楼层（`floors[]`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `index` | 整数 | 否 | 楼层序号：0 = 首层，1 = 二层，负数 = 地下层。楼层按它排序，默认按数组顺序 |
| `elevation` | 数字 | 是 | 本层楼面相对建筑原点的高度（米）。地下层为负数 |
| `height` | 数字 | 是 | 层高（米，楼面到上层楼面），必须大于 0 |
| `name` | 字符串 | 否 | 默认为 `index + 1` 加 "F"。**地下层必须写**（否则 −1 层会显示成 "0F"），如 `"B1"` |
| `outline` | 点列 | 否 | 本层楼板轮廓，与建筑轮廓不同时写（裙楼、退台） |
| `model` | 对象 | 否 | 整层 glTF 模型，见 §7 |
| `rooms` / `things` / `elements` | 数组 | 否 | 房间、设备、构件 |

- 楼板按 `outline`（省略时用建筑轮廓）自动生成，厚 0.25 m，从楼面往下。
- 程序会在楼层属性里自动加上 `楼层`、`标高`、`层高`、`面积`。
- 进入建筑时显示全部楼层（可以开启"楼层展开"，每层拉开 7 m）；进入某一层后只显示这一层。

### 4.4 房间（`rooms[]`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `footprint` | 点列 | 是 | 房间轮廓（楼层本地米），至少 3 个点 |
| `height` | 数字 | 否 | 净高（米），默认层高减 0.3 |
| `walls` | 布尔 | 否 | 是否沿轮廓自动生成墙，默认 true。走廊、开放区、已有整层模型时写 false |
| `doors` | 数组 | 否 | 门洞，见下 |
| `color` | 字符串 | 否 | 地面颜色（CSS 颜色），默认按 `category` 取色（§5.2） |

**门洞**（`doors[]`，只在自动生成的墙上开洞）：

| 字段 | 说明 |
| --- | --- |
| `edge` | 开在哪条边：第 i 条边是从第 i 个点到第 i+1 个点（最后一条回到第 0 个点），从 0 开始编号。必须在 0 到 点数−1 之间 |
| `at` | 门洞中心在这条边上的位置，0 = 起点，1 = 终点，默认 0.5 |
| `width` | 门洞宽度（米），默认 1.0，最多为边长的 90% |

门洞高 2.1 m，上方保留过梁。例如房间 `[[-15, 1.2], [-3, 1.2], [-3, 8], [-15, 8]]`：

```
  (-15,8) ●──── 边 2 ────● (-3,8)        边 0：南侧，(-15,1.2) → (-3,1.2)
          │              │               边 1：东侧
        边 3            边 1             边 2：北侧，(-3,8) → (-15,8)，at 从东往西量
          │              │               边 3：西侧
(-15,1.2) ●──── 边 0 ────● (-3,1.2)
```

程序会在房间属性里自动加上 `面积`，房间顶牌的副标题默认也是面积。

### 4.5 设备（`things[]`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `position` | `[x, y, z]` | 是 | 设备**底部中心**的楼层本地坐标（米），z 是离楼面的高度（吸顶设备写吊顶高度） |
| `rotation` | 数字 | 否 | 绕竖直轴的转角（度，从上往下看顺时针），默认 0 |
| `size` | `[宽, 深, 高]` | 否 | 尺寸（米），宽沿本地 X、深沿本地 Y（未旋转时），默认 `[0.5, 0.5, 0.5]`。用模型时也建议写，顶牌高度按它计算 |
| `shape` | 字符串 | 否 | 没有模型时的简单形状：`box` 长方体（默认）、`cylinder` 圆柱（直径取宽）、`sphere` 球 |
| `color` | 字符串 | 否 | 颜色，默认按 `category` 取色（§5.3）。告警设备可以单独给红色 |
| `model` | 对象 | 否 | 设备模型，见 §7 |

设备只有写了 `label` 才有顶牌。

### 4.6 构件（`elements[]`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `kind` | 字符串 | 是 | 构件种类，只能是 §5.4 列出的 6 种 |
| `path` | 点列 | 二选一 | 墙、窗：折线，至少 2 个点，每段生成一段墙体。楼板：多边形，至少 3 个点 |
| `position` | `[x, y, z]` | 二选一 | 其他构件：长方体的底部中心 |
| `size` | `[宽, 深, 高]` | 否 | 配合 `position` 使用，默认 `[0.4, 0.4, 层高]`。只能与本地坐标轴对齐，不能旋转 |
| `height` | 数字 | 否 | 墙、窗的高度，默认层高 |
| `thickness` | 数字 | 否 | 墙、窗厚度，默认 0.14 m；楼板厚度，默认 0.25 m |
| `color` | 字符串 | 否 | 默认：窗 `#93c5fd`（45% 透明），门 `#a16207`，其他 `#e5e7eb` |

- 墙、楼板、柱子自动带 `structure` 标签：在楼层和房间层级**不参与交互**（不会被选中、悬停），免得挡住房间和设备。门、窗、楼梯可以交互。
- 窗目前从楼面一直到 `height`，没有窗台高度。需要真实门窗外观时用 glTF 模型。
- 房间已自动生成墙时，不要再用 `wall` 构件画同一面墙；门窗构件放在墙外表面以外几厘米，或者把房间设为 `walls: false` 后全部用构件画墙。

### 4.7 外壳（`exterior`）

- 程序生成：沿 `footprint` 拉伸到最高楼层顶，半透明玻璃，每层一道楼板腰线，加屋顶。可调 `color`、`opacity`。
- 模型：`{ "model": { "uri": "shell.glb" } }`，整栋外立面模型。
- 外壳只在地球层级显示，进入建筑后隐藏。点外壳等于点整栋建筑。

### 4.8 顶牌（`label`）

| 字段 | 说明 |
| --- | --- |
| `title` | 主标题，默认实体名称 |
| `subtitle` | 副标题；房间默认是面积 |
| `mode` | 何时显示，见 §5.5。建筑默认 `always`，其余默认 `level` |
| `style` | 外观，见 §5.5。建筑默认 `card`，设备默认 `pin`，房间和构件默认 `tag` |
| `color` | 强调色（CSS 颜色），告警常用 `#ef4444` |
| `icon` | 标题前的短文字或 emoji，如 `"🌡"`、`"⚠"` |
| `offset` | 在默认高度上再抬高的距离（米）。默认高度：建筑在楼顶上 3 m，房间在净高上 0.6 m，设备在顶部上 0.35 m，构件在顶部上 0.3 m |

- 建筑和房间总有顶牌；设备和构件只有写了 `label` 才有。房间不想常显顶牌时，把 `mode` 设为 `hover` 或 `click`。
- 顶牌会自动避让：`card` 样式（建筑、告警）始终显示，其余按 选中 > 悬停 > 房间 > 设备 的优先级，重叠时让位。
- 可见距离：建筑 25 km 内，设备 120 m 内，房间和构件 400 m 内。

### 4.9 视点（`viewpoint`）

进入该实体的层级时相机落在哪里。不写时按层级默认取景：围绕实体包围球的 4 个斜 45° 位置里，选离当前相机最近的一个。

| 字段 | 说明 |
| --- | --- |
| `heading` | 相机朝向，相对建筑本地 +Y 轴顺时针（度）。建筑 `heading` 为 0 时就是相对正北 |
| `pitch` | 俯仰（度），−90 是正俯视，负值向下看，范围 −90 到 90 |
| `range` | 相机到实体包围球中心的距离（米），大于 0 |

三个字段都可以只写一部分，例如只写 `pitch` 让会议室看得更俯视。各层级默认俯仰：建筑 −35°、楼层 −55°、房间 −50°、设备 −35°、构件 −40°。

## 5. 类别与种类

### 5.1 实体类型（固定）

| 类型 | 中文 | 来源字段 | 对应 IFC | 说明 |
| --- | --- | --- | --- | --- |
| `building` | 建筑 | 根对象 | IfcBuilding | 一个文件一栋 |
| `floor` | 楼层 | `floors[]` | IfcBuildingStorey | |
| `room` | 房间 / 空间 | `rooms[]` | IfcSpace | 包括走廊、楼梯间、机房等一切空间 |

## 6. 属性（properties）规范

- 键名用中文，与界面一致：`设备类型`、`状态`、`温度`、`负载`、`所在房间`、`责任人`、`安装日期`。
- 值可以是字符串、数字、布尔。带单位的读数写成字符串并带空格：`"23.4 ℃"`、`"0.42 MPa"`、`"3.8 kW"`、`"41 %"`。查询时 `[温度>26]` 会读出前面的数字比较，所以数字要写在最前面。
- 状态取值统一词表，例如 `正常` / `告警` / `离线` / `维护中`；告警细节写在后面：`"告警：进风温度过高"`（查询用 `[状态=告警*]` 前缀匹配）。
- 日期用 `YYYY-MM` 或 `YYYY-MM-DD`。
- 不要嵌套对象和数组：弹窗只显示第一层，查询也只读第一层。
- 程序自动生成的属性（不用写，写了以文档为准）：

| 实体 | 自动属性 |
| --- | --- |
| 建筑 | `楼层数`、`建筑高度` |
| 楼层 | `楼层`、`标高`、`层高`、`面积` |
| 房间 | `面积` |
| 构件 | `类型`（即 `kind`） |

上表是默认语言（`zh-CN`）下的属性名。宿主以 `GeoViewer.create({ locale: 'en' })` 创建时改为英文：建筑 `Floors`、`Building height`，楼层 `Floor`、`Elevation`、`Storey height`、`Area`，房间 `Area`，构件 `Type`；也可以用 `messages.entityProperties` 逐个改名。选择器和样式规则里引用这些属性时（如 `[面积>20]`），要用当前语言的属性名。文档里自己写的属性名不受影响。

## 7. 使用 glTF 模型

### 7.1 整层模型（`floor.model`）

- 节点的 `name`，或 `extras.id`（glTF 扩展字段，three.js 里是 `userData.id`），等于本层某个房间、设备或构件的 `id` 时，这个节点及其子树就挂到该实体下：可以拾取、高亮、改样式。材质会为它单独复制，改样式不影响别的实体。
- 其余节点是静态几何：照常显示，点到时算作这个楼层。
- 用整层模型时，房间一般写 `walls: false`（墙已在模型里），只保留轮廓用于交互、面积和顶牌。
- 整层模型和本层设备的模型在**楼层第一次显示时**才加载（进入建筑时各层都显示，所以都会加载；从地球直接进入某一层时只加载这一层），不在加载建筑时一次全部下载。进入楼层前会等本层模型加载完（最多 1.5 s）再飞行，保证取景按模型的实际范围计算。
- 显存紧张时，隐藏楼层的模型会被卸载，再显示时重新加载（走浏览器缓存）。预算按机器的显存档位给，一般不用管；楼层模型越小，来回切换越流畅，所以按楼层拆分文件、控制单层大小（§7.3 末尾的建议）仍然重要。

### 7.2 设备模型（`thing.model`）与外壳模型（`exterior.model`）

- 设备模型整体属于该设备，原点放在设备的 `position`（底部中心），再按 `rotation` 旋转。
- 外壳模型只在地球层级显示，随建筑一起加载。

### 7.3 模型引用（`model` 对象）

| 字段 | 说明 |
| --- | --- |
| `uri` | 模型地址。相对路径按 **building.json 文件的地址**解析 |
| `upAxis` | glTF 规范是 Y 轴朝上（默认 `"Y"`，加载时自动转成 Z 朝上）；导出时已经是 Z 朝上的写 `"Z"` |
| `scale` | 统一缩放到米，例如模型单位是毫米写 0.001 |
| `offset` | `[x, y, z]`，转换朝上轴之后的平移（米），把模型原点对到本地坐标原点 |
| `rotation` | 绕竖直轴的转角（度，从上往下看顺时针） |

- 支持 `.glb` / `.gltf`，支持 Draco、meshopt 几何压缩和 KTX2 纹理。
- **拖入本地文件时没有文件地址**，模型的相对路径无法解析：请用 URL 加载（`?building=` 或面板），或把 `uri` 写成完整地址。
- 导出建议：Revit / IFC 用 IfcOpenShell、xeokit-convert 或 Blender（BlenderBIM）导出 glTF，节点名使用 GlobalId；按楼层拆分文件；单个楼层模型尽量控制在 20 MB、50 万三角形以内。

### 7.4 规模

同一楼层里形状相同（或引用同一个模型）的设备合并成一次绘制，1 万个设备约 40 次绘制（[indoor-bim.md](agents/indoor-bim.md) §5.2）。设备上万时仍要控制模型本身的面数；只用来看、不需要交互的东西做成整层模型里的静态几何即可。

## 8. ID 与命名规范

- `id` 全文件唯一，区分大小写。推荐编码：`{楼栋}-{楼层}-{类型}{序号}`，例如 `B-F3-R10`（B 座 3 层 10 号房间）、`B-F1-CAM01`、`B-B1-PU01`。有 IFC 时直接用 GlobalId。
- `id` 只用字母、数字、`-`、`_`。不要用 `.` `#` `[ ]` `( )` `,` 和空格：这些在选择器里有特殊含义，`#id` 查询会被截断（`getById` 不受影响）。
- `name` 面向人，可以用中文和空格，例如 `"303 会议室"`、`"机柜 A02"`。同一层内尽量不重名，便于按名称查询。
- 楼层 `name` 用 `B2`、`B1`、`1F`、`2F`、`RF`（屋顶层）这类写法。

## 9. 校验、加载与自检

### 9.1 自动校验

加载时 `parseBuildingDoc` 会检查下列问题，出错时整份文件不加载，并给出 JSON 路径：

| 问题 | 错误示例 |
| --- | --- |
| 格式标识或主版本不对 | `$.format: expected "three-geo-building"` |
| 缺少或写错必填字段 | `$.anchor.latitude: expected a finite number` |
| id 重复 | `$.floors[1].rooms[3].id: duplicate id "B-F2-R01"` |
| 多边形点数不够 | `$.floors[0].rooms[0].footprint: expected at least 3 [x, y] points` |
| 层高不为正 | `$.floors[0].height: must be positive` |
| 门洞边号越界、位置超出 0..1、宽度不为正 | `$.floors[0].rooms[2].doors[0].edge: expected an edge index 0..3` |
| 构件种类不在 6 种之内 | `$.floors[0].elements[0].kind: expected one of wall, door, window, column, slab, stair` |
| 构件既没有 `path` 也没有 `position` | `$.floors[0].elements[1]: expected path or position` |
| `tags` 不是字符串数组 | `$.tags[1]: expected a non-empty string` |
| `viewpoint` 俯仰超范围、距离不为正 | `$.viewpoint.pitch: must be within -90..90 degrees` |

校验**不会**检查的内容（需要人工自检）：房间是否重叠、设备是否放在房间里、坐标单位是否写错（例如毫米当成米）、`category` 是否拼错、glTF 节点名是否对得上。

### 9.2 交付前自检清单

- [ ] 加载无报错，相机飞到正确位置；建筑朝向与底图道路、相邻建筑一致（`heading` 方向没反）。
- [ ] 从地球看，建筑没有悬空、没有埋进地面（使用倾斜摄影时见 §3.3）。
- [ ] 逐层进入：楼层高度顺序正确，地下层在下面，楼层名正确。
- [ ] 房间轮廓与底图或模型对齐，面积合理（属性弹窗里看 `面积`）；门洞开在正确的墙上。
- [ ] 设备落在正确的房间里（进入房间时，房间里的设备保持清晰、其他变淡）。
- [ ] 顶牌不过多、不互相遮挡；告警用 `card` 样式。
- [ ] 用整层模型时，抽查几个房间和设备能单独点中、高亮。
- [ ] 在控制台核对数量：

  ```js
  viewer.indoor.query('.room').length               // 房间数
  viewer.indoor.query('.thing[category=camera]')    // 所有摄像机
  viewer.indoor.query('tags:or(alarm)')             // 告警实体
  viewer.indoor.query('.room[category=room]')       // 漏填类别的房间（不写时类别默认就是 room）
  ```

## 10. 常见问题

**建筑方向反了或转错了角度。** `heading` 是本地 +Y 轴相对正北**顺时针**的角度。图纸"上方"偏西 10° 时写 −10（或 350）。

**建筑埋在 Google 3D Tiles 里 / 悬在半空。** 写明 `anchor.height`（椭球高，§3.3）。悬空通常是把海拔当成了椭球高，或本地原点不在地坪上。

**地下层显示成 "0F"。** 地下层要写 `name`，例如 `"B1"`。

**门洞没出现。** 检查 `edge` 是否数对了（从 0 开始，第 i 条边是第 i 点到第 i+1 点）；房间是否 `walls: false`（不生成墙，也就没有门洞）。

**墙面闪烁。** 同一面墙既由房间自动生成、又用 `wall` 构件画了一遍，二选一。

**设备在房间外 / 进入房间时设备变淡了。** 设备的 `position` 没落在房间轮廓内；或楼层坐标写成了建筑坐标（楼层内 z 从楼面算起）。

**模型方向躺倒了或大小不对。** Z 朝上导出的模型写 `"upAxis": "Z"`；单位不是米时用 `scale`。

**拖入文件后模型加载失败。** 本地拖入没有文件地址，相对路径无法解析，改用 URL 加载（§7.3）。

**点不中墙或柱子。** 结构构件在楼层和房间层级故意不交互（`structure` 标签），在建筑层级点到它们会选中所在楼层。
