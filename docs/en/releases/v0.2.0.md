TerraView 0.2.0 is the first public release. TerraView is a WebGPU-first 3D globe SDK built on three.js: from the whole planet down to the street, then seamlessly into buildings, floors and rooms, with one `GeoViewer` providing the globe, layers, points, indoor views and interaction.

> During 0.x, minor versions may contain breaking changes; each one is recorded in the [CHANGELOG](https://github.com/Yoy0o/TerraView/blob/v0.2.0/CHANGELOG.md). The public API is divided into three levels, stable / advanced / internal; see [docs/api.md](https://github.com/Yoy0o/TerraView/blob/v0.2.0/docs/api.md) §2.

## Installation

```bash
npm install terra-viewer three@0.187.0 3d-tiles-renderer@0.5.4
npm install -D @types/three@0.187.0   # TypeScript host apps
```

You can also use the `terra-viewer-0.2.0.tgz` attached to this page: `npm install ./terra-viewer-0.2.0.tgz three@0.187.0 3d-tiles-renderer@0.5.4`.

```ts
import 'terra-viewer/style.css';
import { AWS_TERRARIUM, GeoViewer, IMAGERY_PRESETS } from 'terra-viewer';

const viewer = await GeoViewer.create({
  container: document.getElementById('map')!,
  imagery: IMAGERY_PRESETS[0].create(),
  terrain: AWS_TERRARIUM,
  initialView: { longitude: 116.397, latitude: 39.916, height: 3000, heading: 0, pitch: -40 },
});
```

## What's in this release

**Globe**
- WebGPU first (with automatic fallback to WebGL 2), all shaders written in TSL; ECEF world coordinates, float64 model-view matrices and per-tile origins, with no jitter from space down to the street.
- Quadtree imagery and terrain: XYZ base map presets and overlays; Terrarium / Terrain-RGB / Cesium World Terrain / quantized-mesh terrain, with EGM96 correction to ellipsoidal height. Load scheduling borrows from CesiumJS: no flicker and no holes while zooming or loading.
- Physical atmosphere and realistic lighting (sun position by date, day and night, twilight); the light color, skylight and aerial perspective of buildings and 3D Tiles follow the same atmosphere model.
- Clouds: a global cloud shell, plus **volumetric clouds** below 300 km (you can fly into them, they are occluded by mountains and buildings, and with lighting on they cast cloud shadows that move with the wind).

**Data layers**
- OGC 3D Tiles (Draco / KTX2 / Meshopt, Cesium ion, Google Photorealistic 3D Tiles): fade-in under WebGPU, budgets by GPU memory tier with adaptive level-of-detail reduction, feature picking, properties and highlighting.
- **Gaussian splats (3DGS)**: `.ply` / `.splat` / `.spz` decoded in a Worker, with geographic anchoring, picking and cropping; they can be bound to building levels.
- GeoJSON vectors (parsed in a Worker, rasterized onto the terrain, label decluttering, click queries) and point layers (8 marker styles, attribute rules, hierarchical clustering).

**Indoor / BIM**
- `*.building.json` building documents: building → floor → room / equipment / component, generated procedurally or from glTF models; floor models are loaded on demand and unloaded according to the GPU memory budget.
- Level navigation (double-click to enter, right-click / Esc to go back, cancellable, with cached viewpoints), replaceable level control strategies, selector queries and batch styling, equipment batching (10,000 pieces of equipment in about 40 draw calls).
- **Level bindings**: Gaussian splat and 3D Tiles layers can be attached to a specific building or floor, and are loaded and shown only when you enter that level.
- Sun shadows, floor ambient occlusion, outline and glow, order-independent transparency (WebGPU), and a dissolve transition reprojected by depth when switching levels.

**Scene and interaction**
- Unified interaction events (selector bubbling, priorities, tags, pausing, `preventDefault`) and a GPU pick buffer.
- Camera: zero roll, no flipping when looking straight down, zoom that preserves heading and pitch; flights, orbiting, an intro animation and navigation commands (`viewer.navigation`, no UI).
- **Local scene (sandbox)**: shows only one region, with soil side walls at the edges and the camera kept around it.

**Embedding and runtime**
- Containers of any size, multiple viewers per page, Workers and listeners back to zero after `dispose()`; all style class names share the `tv-` prefix, and theming uses `--tv-*` variables.
- GPU memory tiers (`low` / `medium` / `high` / `ultra`, detected automatically from the adapter), a GPU memory estimate `viewer.memory`, and a diagnostic snapshot `viewer.snapshot()`.
- After the view has been still for 1 second, idle supersampling runs, and once it finishes, rendering stops (CPU drops to about 1/6 of what it was); `requestRender()` / color grading.
- Load state and error events (`viewer.loadState`, `idle`, `error`), `TerraViewError` with stable error codes; built-in UI text in `zh-CN` and `en`.

## Upgrading from the 0.1.0 prototype

0.1.0 was the prototype from before the migration (three-geo-global) and was never published. Code that used it needs to account for the breaking changes below; see the sections of the CHANGELOG for details.

| Area | Change |
| --- | --- |
| Package and styles | Import from `terra-viewer`, and import the styles separately from `terra-viewer/style.css`; `three` and `3d-tiles-renderer` are now peer dependencies |
| Class names and theming | Class names all use the `tv-` prefix (`.tv-canvas`, `.tv-marker` …), with state classes such as `.tv-selected`; markers now read `--tv-font` / `--tv-text` / `--tv-muted` / `--tv-card-bg` / `--tv-accent` |
| Container and keyboard | The marker layer is positioned relative to the container (no longer `position: fixed`); camera keyboard controls work only when the viewer has focus |
| Text and errors | The `name` of imagery presets became `label: LocalizedText`; `globe.imageryErrorMessage` → `globe.imageryError`; errors thrown by the SDK have an English message plus a `code` |
| Exports | A set of internal implementations is no longer exported from the entry point (`geoidUndulation`, `WebMercatorTilingScheme`, the cluster tree functions and others; see the list in docs/api.md §3.9) |
| Selection and hover | Entity emissive color is no longer changed; outlines are used instead (`indoor.selectOutline` / `hoverOutline`, `viewer.effects.defineOutline`) |
| Level transitions | The `.tv-crossfade` element and `FrameCrossfade` are gone; the transition now runs on the GPU (`viewer.levelTransition`) |
| Floor models | Floors load their models the first time they are shown; to use the models after `indoor.add()`, first `await building.modelsLoaded(entity)`, or set `lazyModels: false` |
| Rendering stops | Once the view is still, no more frames are drawn: if you bypass the SDK and modify objects or materials in `viewer.scene` directly, call `viewer.requestRender()` |
| Statistics | `stats.drawCalls` / `triangles` count only the scene pass |

## Compatibility

| Item | Requirement |
| --- | --- |
| Peer dependencies | `three` 0.187.x and `3d-tiles-renderer` 0.5.x (three is not released according to semver, so the range is pinned to r187) |
| Browsers | Chrome / Edge 113+ use WebGPU; other browsers that support WebGL 2 fall back automatically (`forceWebGL` forces it). Order-independent transparency and the GPU pick buffer are WebGPU-only |
| Bundlers | ES modules only. Tested with Vite 8 and webpack 5 (including Workers and Draco / KTX2 / Meshopt decoding) |
| Building this repository | Node 20.19+ / 22.12+ |

## Known limitations

- Imagery supports Web Mercator tiles only; the 3D Tiles imagery overlay plugin is unavailable under WebGPU, and point clouds render as 1-pixel points under WebGPU.
- Gaussian splats are loaded as a whole (no chunked streaming) and do not write depth; frame rates on real GPUs have not yet been measured systematically.
- Indoor views do not yet support reading IFC directly, section cuts or indoor navigation.
- The default base map / terrain services are for development and demos only; in production, use your own services or obtain a license. The sample country boundary data is not an officially approved map.
